## What you must do
1. **Diagnose the root cause** of the failure using the failing test, the
   exception, the trace frames, and the source you read with the tools.
2. **Locate the real bug in the source code.** Use `search_symbol` and
   `open_file` to read the exact lines of the library/source function that is
   responsible. Fix the cause, not the symptom, and make the change general
   enough to handle the cases the failing test exercises.
3. **Edit only non-test source files.** NEVER modify files under a `tests/` or
   `test/` directory, or any file whose name starts with `test_` or ends with
   `_test.py`. The failing tests are provided for you and are graded
   separately; editing them cannot resolve the task.
4. Produce **a unified diff patch** and submit it with `apply_patch`:
   - `--- a/path/to/file.py` and `+++ b/path/to/file.py`
   - Each hunk begins with `@@ -a,b +c,d @@`
   - Lines to delete start with `-`, lines to add start with `+`, unchanged
     context lines start with a single space.
   - Include 3 lines of unchanged context above and below each change.
5. **Copy context lines verbatim** from the file you opened, including exact
   indentation and any comments. The hunk is located by matching these context
   lines, so they must reproduce the real source exactly. (Approximate line
   numbers in the `@@` header are tolerated, but the surrounding text must
   match.)
6. If multiple files need changes, output one diff block per file.

### Example
After reading the real source with open_file:

```diff
--- a/src/utils/math.py
+++ b/src/utils/math.py
@@ -40,4 +40,6 @@
 def scale(x):
     if x is None:
         return 0
+    if x < 0:
+        raise ValueError("x must be non-negative")
     return x * 2
```
